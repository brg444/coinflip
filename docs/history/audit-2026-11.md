## 3. Code Audit — Ranked Findings

### Critical

#### [F-01] Predict positions announced on Nostr are silently dropped by both Oracle and Settler
- **Location:** [protocol/nostr.ts](file:///Users/alexb./code/arkade-options/protocol/nostr.ts#L74-L95), [desk/main.ts](file:///Users/alexb./code/arkade-options/desk/main.ts#L388-L409), [desk/main.ts](file:///Users/alexb./code/arkade-options/desk/main.ts#L573-L611), [oracle/main.ts](file:///Users/alexb./code/arkade-options/oracle/main.ts#L99-L105), [settle/main.ts](file:///Users/alexb./code/arkade-options/settle/main.ts#L281)
- **Root cause:** `readPosition()` requires `position.holder_pubkey === event.pubkey`. For Predict (`kind 2/3`), the desk is the **writer** (`writer_pubkey`), so desk-signed NIP-78 announcements (`event.pubkey === writer_pubkey`) are silently dropped.
- **Impact:** Automatic oracle publishing and automatic settlement of COINFLIP bets are completely non-functional over Nostr (including in `pnpm demo`). Because an unsettled Predict vault defaults to the desk via unilateral exit (**N-4**), this is a fund-safety bug for bettors, not only a liveness bug.
- **Fix:** Accept either party's signature (`position.holder_pubkey === event.pubkey || position.writer_pubkey === event.pubkey`) in `readPosition()`, combined with **N-1** beacon/vault filtering on the oracle and settler. Add regression tests in `protocol/protocol.test.ts` and `settle/predict.test.ts`.

### High

#### [F-02] `OptionIntent.finalize` and `StandingLeg.fill` allow multi-input output sharing
- **Location:** [contracts/option_intent.ark](file:///Users/alexb./code/arkade-options/contracts/option_intent.ark#L30-L56), [contracts/standing_leg.ark](file:///Users/alexb./code/arkade-options/contracts/standing_leg.ark#L27-L61)
- **Root cause:** `OptionIntent.finalize()` checks `tx.outputs[0]` and `tx.outputs[1]` at fixed indices without binding `this.activeInputIndex`. If a bettor pays the same intent address twice, the desk can sweep both stakes in one finalize tx while funding one vault. (`StandingLeg.fill()` bounds `tx.numInputs == 2`, which still allows two same-side writer legs to share outputs without any outside capital—worse than `OptionIntent`, though COINFLIP does not use `StandingLeg`.)
- **Fix (ships immediately on `0.1.0-rc.1`):** Add `require(this.activeInputIndex == 0, "intent is input 0");` in `OptionIntent.finalize()` and `require(this.activeInputIndex == side, "leg input index");` in `StandingLeg.fill()`. Recompiling only those two contracts under `0.1.0-rc.1` changes per-quote intent/leg addresses only—no beacon or vault address changes and no waiting for SDK compiler-0.1.0 support.

#### [F-11] Page does not verify `quote.profile.beacon_txid` against its pinned beacon
- **Location:** [app/src/rfq.ts](file:///Users/alexb./code/arkade-options/app/src/rfq.ts#L105-L128), [app/src/rfq.ts](file:///Users/alexb./code/arkade-options/app/src/rfq.ts#L230-L254)
- **Root cause:** `requestQuotes` and `requestPredictQuotes` accept any 64-hex `beacon_txid` from the desk without checking it against `LIVE_BEACON_STATUS`.
- **Impact:** A dishonest or compromised desk can bind a bettor's vault to an attacker-controlled beacon and attest arbitrary prices. Pinning `beacon_txid` + `beacon_gidx` on the page is the bettor's only protection against a desk-chosen oracle.
- **Fix:** Unconditionally reject quotes whose `beacon_txid` or `beacon_gidx` does not match `LIVE_BEACON_STATUS` (including in `pnpm demo` once its beacon is deployed).

#### [N-1] Unauthenticated Nostr spam can force the oracle to attest arbitrary expiries and evict live fixings
- **Location:** [oracle/main.ts](file:///Users/alexb./code/arkade-options/oracle/main.ts#L99-L105), [oracle/service.ts](file:///Users/alexb./code/arkade-options/oracle/service.ts#L526-L544), [settle/main.ts](file:///Users/alexb./code/arkade-options/settle/main.ts#L137-L142)
- **Root cause:** `oracle/main.ts` adds `position.expiry` to `announced` for every `readPosition` event without checking `beacon_txid`, vault existence, recency, or grid alignment. Any Nostr key can sign fake positions naming itself as holder and flood `attest()`, holding the single-flight `publishing` lock, evicting real fixings from the 8-slot beacon, and lengthening beacon ancestry.
- **Fix:** In both `oracle/main.ts` and `settle/main.ts`, filter positions to our own `beacon_txid`/`beacon_gidx`. In `oracle/main.ts`, additionally require the expiry to be recent (within the last hour), on the 300s grid for Predict (`kind 2/3`), verified to have an unspent vault VTXO on the indexer at `position.vault_address` before auto-publishing, and cap auto-publishes per pass (newest first, dropping once published).

#### [N-2] Offchain VTXO expiry inheritance can brick the shared beacon coin (replaces & sharpens F-08)
- **Location:** [desk/fill.ts](file:///Users/alexb./code/arkade-options/desk/fill.ts#L67-L157), [oracle/service.ts](file:///Users/alexb./code/arkade-options/oracle/service.ts#L415-L479), [contracts/attestation_beacon.ark](file:///Users/alexb./code/arkade-options/contracts/attestation_beacon.ark)
- **Root cause:** `arkd` assigns every output of an offchain tx the earliest expiry among all inputs (`SubmitOffchainTx`), and refuses to spend expired/swept coins offchain (`VTXO_RECOVERABLE`). Because `settle` co-spends each vault with the single beacon coin, **one** bettor stake coin funded from a near-expiry VTXO ratchets the vault—and then the shared beacon—down to that near-expiry timestamp, making every open vault unsettleable. Furthermore, SDK wallet renewal does not renew covenant coins (`AttestationBeacon` has no `renew` leaf).
- **Fix:** For beta (`desk/fill-guards`): surface beacon coin expiry in `/api/status`, refuse quotes that would outlive the beacon, and in `desk/fill.ts` refuse to finalize when the stake coin or any picked float coin expires before `expiry + 60` plus safety margin (letting the stake refund via `cancel`). Coordinate a `renew` leaf with Marco for the compiler-0.1.0 / next beacon generation.

#### [N-3] 60-second lock without fill-time re-pricing gives bettors a positive-EV free look against desk float
- **Location:** [desk/main.ts](file:///Users/alexb./code/arkade-options/desk/main.ts#L395), [desk/fill.ts](file:///Users/alexb./code/arkade-options/desk/fill.ts#L53-L157)
- **Root cause:** The desk quotes from a 10s-cached spot and sets a 60s lock (`PREDICT_LOCK_S`), then `fillQuote()` finalizes any stake arriving before `deadline` with no price re-check. Requesting both Higher and Lower at spot and funding only the winning side at `t = 59s` wins 74.7% on a 120s window and 54.1% on a 60m window (both above the 52.6% break-even at 1.90×, yielding 1.03×–1.42× expected return).
- **Fix:** In `desk/fill.ts` (`desk/fill-guards`), re-price Predict fills against live spot/DIA price before finalizing, and decline (letting the stake refund after deadline) if the fair multiplier has dropped below the quoted multiplier beyond tolerance.

## 4. Dependency & Stack Review

### 4.1 Upstream `ArkLabsHQ/arkade-options` (#56–#61) & DIA Timing Answer
- **On-chain DIA cadence:** Queried `https://rpc.diadata.org/` across **23.67 hours** (3,409 updates from pinned signer `0x10e34723aa722c7a9860f5ec6446f22252db168a` derived from `DIA_PUBKEY`): exact **25-second cadence** (`min = p50 = p99 = max = 25s`, 0 gaps > 25s). **284 / 284 (100%)** of 5-minute closes had 2–3 valid signed updates inside `[expiry, expiry + 60]`.
- **60s-poll phase-aliasing exposure:** Upstream's `oracle/service.ts` polls `feed.latest()` every 60s, creating 50s and 75s gaps (verified on the hosted oracle: 120×50s, 79×75s). Exactly **140 / 1,500 (9.3%)** `(DIA phase mod 25, poll phase mod 60)` alignments miss every consecutive 5-minute close (whenever DIA's phase lands in `11..24` mod 25; today DIA sits at phase `2`, so 0/40 missed on the hosted oracle, but any DIA restart re-rolls the phase).
- **Fix:** Set `SAMPLE_MS=20000` (0/750 phase pairs miss) AND persist every distinct pinned DIA intent delivered on the WebSocket (upstreamable fix for Marco).
- **Basis risk:** Already exists today (desk quotes Coinbase/Kraken/Binance median vs Deribit settlement); mitigated in Branch 7 by quoting from the oracle's DIA print with exchange median as a sanity band.

- **`OptionIntent.cancel` refunds:** Blocked by lack of `after_timestamp` scheduling (`schema.Schedule` only has `immediate`, `before_expiry_seconds`, `min_confirmations`; `locks.go` forbids locktime on `virtual` templates; early `CHECKTIME` rejections trip `TEMPLATE_MAX_FAILURES = 10` and disable the template). Revisit once `executord` adds wall-clock scheduling.
- **`PredictVault.settle`:** Not feasible on `v0.0.4` (5 blockers: no conditional/computed output routing from packet 32, external oracle publish required, no cross-delegation locking on the shared singleton beacon coin, 1 trigger per template, daemon test emulator skips covenant execution).

### 4.6 Throughput Measurement & Scaling Options
- Measured live Mutinynet RTTs (`oracle /api/status` 697ms, `/api/prices` 260ms, `indexer getVtxos` 329ms, `getVirtualTxs` 513ms, `emulator /v1/info` 527ms, `arkd /v1/info` 490ms). One `settle/main.ts` pass takes ~3–4s (~15 vaults/min, ~75 vaults per 5-minute close; the 2s interval overlaps execution rather than adding on top, though returning after 1 settle still waits for the next tick).
- Above ~60–75 bets per 5-minute close a backlog grows; past 40 minutes the 8-slot beacon hits eviction thrashing; **N-1** and permissionless `read` (1,000 sats/call) allow external contention too.
- **Scaling options (no contract changes in this task):** (1) Settler pipelining chaining the returned `signedArkTx` beacon outpoint directly + caching `/api/status` & `/api/prices` (~3× gain), (2) Sharded `K`-beacon pool (`K×` throughput and `K×` slot retention, zero contract changes), (3) Direct DIA `checkSigFromStack` inside `PredictVault.settle` (unlimited parallelism, future redesign), (4) Multi-vault batched beacon `read` (future redesign).
